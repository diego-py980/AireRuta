# Lista de verificación antes de entregar AireRuta

## Pruebas manuales 

- [ ] Abrir `index.html` y verificar que aparece el menú lateral en escritorio.
- [ ] En móvil, abrir menú hamburguesa y usar navegación inferior.
- [ ] Escribir un destino en Inicio y comprobar que aparece en Planifica tu recorrido.
- [ ] Cambiar medio de transporte y prioridad; comparar rutas.
- [ ] Seleccionar las rutas A, B y C; comprobar tiempo, distancia y exposición ilustrativa.
- [ ] Comparar las rutas en la tabla y acceder al detalle.
- [ ] Guardar una ruta, consultarla desde «Mis rutas» y eliminarla.
- [ ] Seleccionar una ruta: debe aparecer en Historial.
- [ ] Filtrar Historial y revisar el resultado.
- [ ] Cambiar preferencias y verificar que se guardan tras recargar.
- [ ] Cambiar el nombre del perfil y verificar la actualización.
- [ ] Marcar las alertas de ejemplo como leídas.
- [ ] Recorrer con Tab y Enter los botones, enlaces y formularios.
- [ ] Confirmar que la web indica claramente que las rutas y datos ambientales son simulados.
- [ ] Contrastar estilos y pantallas con `docs/referencias_figma/`.
- [ ] Completar la matriz de las 30 historias de usuario (HU, criterio, evidencia, cumple/no cumple).
- [ ] Ejecutar pruebas con participantes reales sobre la página publicada.

## Evidencias necesarias para el informe

- **5.5:** captura de la raíz del repositorio y URL de GitHub.
- **5.6:** URL pública de GitHub Pages y capturas de PC/móvil.
- **6.1:** tabla de pruebas de aceptación por HU con resultados comprobados.
- **6.2:** registros de pruebas con participantes, capturas y síntesis de hallazgos.
- **6.2.3 y 6.2.4:** formulario SUS de diez ítems estandarizados y resultados reales sin inventar puntajes.

## Diferencias conocidas respecto al Figma

Los mockups muestran diseños de alta fidelidad, pero no incluyen automáticamente el backend ni fuentes de datos. Esta implementación reproduce patrones visuales y las pantallas principales, usando un mapa SVG ilustrativo en vez de un mapa conectado a una API. El equipo debe ajustar la correspondencia exacta y completar funcionalidades antes de afirmar que el prototipo satisface todas las historias de usuario.
